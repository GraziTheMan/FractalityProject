# Fractality Platform — Full Codebase Audit

**Date:** 2026-08-17
**Audited version:** v0.13.0 (commit `f83fec7`) → v0.13.1
**Scope:** the whole repository — 264 files, ~74k lines of JavaScript, 35 Python modules

---

## Executive summary

Before this audit, **the application could not be built, served, or loaded.**
Not "had bugs" — it could not start. Ten JavaScript files did not parse, five
Python modules did not compile, the package manifest contradicted every source
file in the repo, and the single line responsible for booting the 3D engine
called a method that did not exist.

After this audit the project builds, boots in a browser with zero console
errors, renders its 36-node test graph at interactive frame rates, and has a
test suite and a repeatable health check.

| | Before | After |
|---|---|---|
| JS files that parse | 95 / 105 | **all** |
| Python files that compile | 30 / 35 | **all except one archived file** |
| Unresolved relative imports | 40 | **0** outside `archive/` |
| Broken HTML asset references | 18 | **0** outside `archive/` |
| `npm run build` | did not exist | **succeeds** |
| Page loads without JS errors | no | **yes** |
| Automated tests | 3 empty placeholder files | **20 passing** |

The single most useful finding is not any individual bug but the **cause**: the
overwhelming majority of defects trace to a handful of mechanical copy-paste
failure modes, each with a recognisable signature. Those signatures are now
encoded in `scripts/health-check.mjs`, so they cannot silently recur.

## Part 1 — Root causes

Rather than 60 unrelated bugs, this was five repeated mistakes.

### 1.1 Truncation at a copy limit (3 files, ~15 methods lost)

Three files were **exactly** 20,000 / 20,004 / 20,028 bytes and ended
mid-identifier:

```js
siblingEl.dataset.nodeId = node.s          // NodeInfoPanel.js, cut here
const audioAgent = this.agentNetwork.getNode('age   // FractalAIPrototype.js
import { Consciousn                        // ConsciousnessNode.js
```

A file ending mid-token at a round 20,000 bytes is not a coding error, it is a
chat window's copy ceiling. Two more files (`data-console.html` at 20,011 and
`DebugShell.html` at 20,039) share the signature and are still truncated in
`archive/`.

**What was lost.** `NodeInfoPanel.js` lost nine methods —
`_onTreeNodeClick`, `_navigateToNode`, `_expandNode`, `togglePin`,
`_setupEventListeners`, `_animateOpacity`, `_getScoreColor`,
`_getRelationshipLabel`, `_formatValue` — every one of them called from the
surviving code. `FractalAIPrototype.js` lost six.

**Fixed** by completing the cut method and reconstructing the missing ones
against their existing call sites. Navigation follows the `nodeSelected` window
event that `SearchInterface` already used, so the restored code matches the
project's own convention rather than inventing a new one.

### 1.2 Markdown rendering ate the source (5 Python files)

The clearest single diagnosis in the audit. Three `core/field_engines/` modules
contained **zero** occurrences of `__init__`, while their working sibling
`superionic_database_enhanced.py` contained four. The damage:

| Original | As committed |
|---|---|
| `def __init__(self):` | `def init(self):` |
| `if __name__ == "__main__":` | `if name == "main":` |
| `"""docstring"""` | bare text |
| `# comment` | bare text |
| two lines | one merged line |

Double underscores are Markdown's bold/italic markers. This code was pasted
from *rendered* Markdown, not from a code block — which also explains the
collapsed newlines (rendered paragraphs) and the stripped `"""` and `#`.

```python
# What was committed:
class OntologyGraph: def init(self): self.nodes = {} self.edges = defaultdict(list)

# What it had to be:
class OntologyGraph:
    def __init__(self):
        self.nodes = {}
        self.edges = defaultdict(list)
```

**Fixed** by reconstructing all five files. `field_glyph_generator.py` and
`superionic_database.py` were then run to confirm they produce correct output.

### 1.3 Multi-file AI responses pasted into one file (2 files)

When an assistant emits several files in one reply, the separators say where
each belongs. Those separators were pasted along with the code:

```js
// ===========================
// src/core/EventBus.js          ← this is a filename, not a comment
// Central event system
export class EventBus { ... }
```

`src/mobile/MobileApp.js` was **five** modules concatenated, and it imported
`EventBus`, `MobileConfig`, `HapticFeedback` and `AnimationEngine` from paths
that did not exist *while also defining all four in its own body* — plus, at
line 504, an import of itself. It failed to parse on
`Identifier 'EventBus' has already been declared`.

`src/ecs/ECS.js` had the same shape: it exported nothing at all, ran a demo
world at import time, and `main.js` imported `./ecs/components.js` and
`./ecs/systems/*.js` — the exact split the file's own comments described.

**Fixed** by splitting both at their separators, into the paths those
separators named.

### 1.4 Escaped template literals (4 files)

```js
this.root.innerHTML = \`
  <div class="menu-actions \${this.open ? 'open' : ''}">
```

`\`` and `\${` are what you get when a template literal is nested inside
another template literal and the outer layer is stripped. Four `ui/` modules
were unparseable because of it.

### 1.5 Divergent duplicates, where the *stale* copy was live

Four `main.js` files, two `index.html`, five `package.json`. The dangerous case
was not the duplication but which copy won:

- `public/components/radialMenu.js` (live) **lacked `setHandedness()`**.
  `mirrorToggle.js` calls it on every Mirror click, so the button threw a
  `TypeError`. The *archived* copy still had the method — the older file was the
  more complete one.
- `public/index.html` linked `./src/styles/main.css`, a path that only resolves
  from the repository root. It had been moved *into* `public/`, breaking all
  three stylesheet links.

## Part 2 — Findings that were not copy-paste damage

### 2.1 SECURITY: AI provider keys in browser code

**Severity: high.** `src/chat/FractalityChat.js` runs client-side and did this:

```js
this.apis = {
    claude: new Anthropic({ apiKey: config.claudeKey }),
    gpt: new OpenAI({ apiKey: config.openaiKey }),
    ...
```

fed from `src/config/chatConfig.js`:

```js
claudeKey: process.env.ANTHROPIC_API_KEY || 'your-claude-api-key',
```

Two independent problems:

1. **`process.env` does not exist in a browser bundle.** Reading it throws a
   `ReferenceError` at module load. So this code could never have run.
2. **Had it "worked", it would have been worse.** Any key reachable from client
   code is bundled into the JS served to every visitor, readable in devtools,
   and spendable against your quota.

**Action taken:** the key fields are now explicitly empty, with the reasoning
documented in place, and `chatConfig` reads an optional `VITE_AI_PROXY_URL`
instead. `FractalityChat` throws a clear error naming the missing credentials
rather than constructing SDK clients with `undefined`.

**Still outstanding:** the actual fix is a server-side proxy. `server.js` is the
natural home — it can hold real keys in its own environment. Until that exists
the chat module is intentionally not importable, and its three SDKs are
deliberately absent from `package.json`.

### 2.2 The packaging manifest contradicted the entire codebase

`package.json` declared `"type": "commonjs"` with dependencies of exactly
`express`, `socket.io` and `url`. Meanwhile:

- every file in `src/` is an ES module
- `src/` imports `three`, which was **not a dependency**
- `vite.config.js` existed, and `vite` was **not a dependency**
- `vite.config.js` pointed at `./index.html`, which **did not exist** (it was in `public/`)
- `server.js` served `__dirname` and fell back to a root `index.html`, so in
  production **every route 404'd**
- `server.js` had an explicit `/chat` route serving a `chat.html` that lives in the archive
- four *other* `package.json` files disagreed about name, version and module type

`render.yaml` compounded it: `buildCommand: npm install` with no build step, so
the deployed site would have served raw ES modules containing a bare `three`
import that no browser can resolve.

**Fixed.** One manifest, `type: module`, `three` + `vite` declared, real
scripts. `server.js` converted to ESM, serves `dist/` when built and warns when
not. `render.yaml` now builds. The four duplicate manifests are gone.

### 2.3 Modules imported but never written (3 files)

Not damage — code written against modules that were never created:

| Missing module | Imported by | Resolution |
|---|---|---|
| `src/intelligence/ResonanceEngine.js` | `MobileApp`, `ResonanceFeedController` | Implemented, local-only |
| `src/visualization/ParticleFieldRenderer.js` | `MobileApp` | Implemented, canvas-2D |
| `core/agent_systems/ExecutiveAgent.js` | `scripts/test_loop.js` | Implemented |
| `core/field_engines/phase_engine.py` | `consciousness_user.py` (×2 methods) | Implemented |

Each was written against the API its callers already assumed — method names,
arguments and return shapes were all recoverable from the call sites.

`phase_engine.py` is worth a note. `ConsciousnessUser` already declared
`LIQUID_THRESHOLD = 200.0  # Energy * frequency` and
`SUPERIONIC_THRESHOLD = 50000.0`. Taken literally, a brand-new user
(energy 100 × frequency 432 = 43,200) would classify as LIQUID immediately —
yet the enum documents `SOLID` as *"New users, fixed patterns"*. Driving phase
from the frequency **gain** over the 432 Hz baseline makes every threshold land
correctly: a new user has gain 0 → SOLID, and 100 × 500 Hz = 50,000 → SUPERIONIC.
The thresholds are read from the user class rather than duplicated.

### 2.4 A dead loader, and `THREE` undefined in four modules

`FractalityEngine`, `FractalityRenderer`, `AnimationSystem` and
`EnergyVisualizer` all began with:

```js
import { loadThreeJS, getEnvironmentInfo } from '../utils/ThreeJSLoader.js';
```

…and **never called either function**, then used a bare `THREE` that was
therefore always `undefined`. `ConsciousnessNode.js` used `THREE` 18 times with
no import at all.

The loader itself could not have helped: it is async and returns `{ THREE }`,
but every consumer used `THREE` synchronously in its constructor. It was also
the source of Vite's "dynamic import cannot be analyzed" warning.

**Fixed** with a static `import * as THREE from 'three'` in all five, which the
bundler resolves and tree-shakes. `ThreeJSLoader.js` is retained but is no
longer on the critical path.

### 2.5 The bug that kept the visualizer dark

`src/utils/appState.js` was nine lines:

```js
export const AppState = {
  currentView: 'bubble',
  setView(view) {
    const content = document.getElementById('content-view');
    content.innerHTML = `<div ...>Switched to: <strong>${view}</strong></div>`;
  }
};
```

But all three `main.js` variants contain:

```js
AppState.on('viewChanged', async (view) => {
  if (view === 'bubble' && !fractalityEngine) {
    fractalityEngine = new FractalityEngine('fractality-canvas');
    ...
```

`AppState` has no `on`. That line — the one responsible for constructing the
engine, loading data and starting the render loop — threw
`TypeError: AppState.on is not a function` and aborted the rest of module
initialisation. **The 3D visualizer had never run.**

A second bug hid behind it: `setView` overwrote `#content-view`'s `innerHTML`,
and `#fractality-canvas` is a child of `#content-view`. Any view switch would
have destroyed the canvas the renderer holds a reference to.

**Fixed.** `AppState` now has a real `on`/`off`/`emit` (async-aware, with
per-handler error isolation), placeholder text renders into its own element so
the canvas survives, and `main.js` sets an initial view so something is on
screen at load.

### 2.6 Neither stylesheet styled the actual page

`index.html` declares `#radial-menu`, `#state-indicator`, `#mirror-toggle`,
`#content-view`, `#biometric-panel`. But `main.css` styles `#canvas`,
`#ui-overlay`, `#controls` — an older DOM — and `mobile-menu.css` styles
`#menu-root`, `#menu-container` — `MenuController`'s DOM. Of the shell's
elements, only `#desktop-dock` had any rules.

The visible consequence: `#radial-menu` had no dimensions, so
`getBoundingClientRect()` returned ~0 and `RadialMenu.render()` stacked all
nine buttons on one point.

**Fixed** with `src/styles/shell.css`, matching the existing cyan-on-black
conventions. `RadialMenu` now also clamps its radii to its container and
re-lays-out on resize, so the fan is responsive instead of clipped.

### 2.7 Assorted correctness bugs

- `TriadicConsciousnessEngine` instantiated `SharedConsciousContext` **without
  importing it** — constructing the engine threw `ReferenceError`. Now tested.
- `main.js` called `testGenerator.generatePattern()`; the method is
  `generateTestPattern()`. Further, `'golden'` was not one of its cases despite
  `generateGoldenSpiral()` existing, so it would have silently fallen through
  to `default` and returned the trivial graph. Added `golden`/`spiral`/
  `balanced`/`organic` so the five patterns the README advertises are reachable.
- `def 8x8x8_cube_preparation` — a Python identifier cannot begin with a digit.
- `core/field_engines/superioronic_database.py` was misspelled ("superi-**ro**-onic").
  Two modules do `from superionic_database import SuperionicDatabase`, so they
  could never have imported it. Renaming fixed all three at once.
- `graph-chat-sync.js` imported `./init.js`; the file is at `src/main/init.js`,
  and it did not export `nodeGraph`.
- `FractalityRenderer` set `outputEncoding`/`sRGBEncoding`, removed in three r152+.
- `consciousness_backend/requirements.txt` was **empty** (2 bytes). Reconstructed
  from actual imports across the Python tree — 16 packages.
- `MainMenuRadial.js` used `assert { type: 'json' }`, a withdrawn proposal.
- The ECS ran a second uncapped `requestAnimationFrame` loop at a hardcoded
  1/60 delta. Now uses real elapsed time and pauses on tab hide.
- `MenuController.destroy()` calls `this.eventBus.off('node:focus')` with no
  handler argument, which is a silent no-op — listeners leak. **Not fixed**;
  flagged below.

### 2.8 Dead weight removed

- `transfer/` — a 25-byte `<!-- Placeholder HTML -->` and a 2-line manifest
- `json/` — two stale `package.json` copies parked in a folder named `json`
- `server/` — a stale manifest, an empty `start.md`, and a README byte-identical

- 20 one-byte placeholder files (`start.md`, `Start.md`, empty per-directory

- 3 empty test files that made `npm test` pass vacuously. `tests/test_mindmap.py`

1. **Server-side AI proxy.** Required before the chat module can be enabled at
   all. See §2.1.
2. **`ResonanceEngine` has no network behind it.** It persists to
   `localStorage` and seeds four sample pulses. The social half of "social mind

11. **`src/` and `core/` overlap confusingly.** Two `CACEEngine.js` and two

## Part 5 — Follow-up: deployment preparation

A second pass, done while preparing the app to deploy at fractiverse.com as a
static site. It turned up four more defects, two of them security-relevant.

### 5.1 A second place shipping API keys to the browser

§2.1 covered `src/chat/`. `src/mobile/chat-ai-hub.js` was doing the same thing
independently and had been missed:

```js
export async function initAIBot(openaiKey) {
  const resp = await fetch('https://api.openai.com/v1/chat/completions', {
    headers: { 'Authorization': `Bearer ${openaiKey}` },
```

A raw OpenAI key, passed into client code, sent from the browser. Rewritten to
call a server-side proxy (`VITE_AI_PROXY_URL`) and to stay disabled until one is
configured. **Lesson for the audit itself:** finding one instance of a pattern is
a reason to grep for the pattern, not to close the finding.

### 5.2 Stored XSS in the feed renderer

`ResonanceFeedController._createPulseElement()` built markup with `innerHTML`
and interpolated `pulse.title`, `pulse.preview`, `author.name`, tags and
`media.url` **unescaped**. Harmless while the feed is seeded locally; the moment
strangers can post, a single title containing `<img src=x onerror=...>` executes
in every reader's browser.

Fixed by escaping every user-authored value and validating URLs through a new
`src/utils/sanitize.js` (`escapeHtml`, `safeUrl`, `safeCssValue`). `safeUrl`
rejects `javascript:`/`data:` schemes including control-character obfuscation
(`java\nscript:`), which a naive `startsWith` check misses. 12 tests cover the
payloads.

This is the highest-priority finding for the stated goal of a public social
feed. Note it is a *mitigation*, not a solution: the renderer still uses
`innerHTML`. Server-side validation is still required, and moving that renderer
to DOM construction would remove the class of bug entirely.

### 5.3 Named imports that resolved to `undefined`

Two files imported names their target never exported:

- `chat-ai-hub.js` imported `{ chatSocket }` from `chat-client.js`, which only
  exported `initChatUI`.
- `chat-ui.js` imported `{ initChatUI }` **from itself** — the same snippet had
  been pasted into both it and `mobile-ui.js`.

Both resolved to a real file, so the original health check passed them. It now
parses each module's exports and verifies named imports against them; verified
by deliberately breaking an import and confirming a non-zero exit.

### 5.4 Deploy-hostile hardcoded hosts

- `NodeBridge` hardcoded `http://localhost:8001` and probed it on every page
  load. On a deployed site that is unreachable, and on HTTPS it is blocked
  outright as mixed content — a guaranteed failed request for every visitor.
- `chat-client.js` hardcoded `https://thefractalityplatform.onrender.com`, a
  previous deployment, so any new deploy would have talked to the old one. It
  also opened the socket at *module import* time and loaded socket.io from a
  CDN.

Both now read from `src/config/deploy.js`, the single source for
environment-derived config. The CLI bridge defaults to localhost during `vite
dev` only; chat is disabled unless `VITE_SOCKET_URL` is set; socket.io-client
comes from npm via a dynamic import, so it is code-split out of the main bundle
(confirmed: 0 occurrences in `main-*.js`).

**Verified:** the production build now loads with **zero page errors and zero
failed network requests**, while `vite dev` still probes the CLI bridge, so the
local CLI workflow is intact.

One cosmetic wart: `deploy.js` reads env vars through a helper function, so Vite
cannot statically replace `import.meta.env.DEV`, and the string
`http://localhost:8001` remains in the bundle as dead weight (~25 bytes). The
runtime behaviour is correct; the literal is never used in production.

## Appendix — Preventing recurrence

`npm run health` checks for the specific failure modes documented above:

| Check | Catches |
|---|---|
| ESM parse of every JS file | escaped template literals, stray braces, truncation |
| `py_compile` of every Python file | merged lines, bad identifiers, indentation |
| Relative import resolution | modules that were never created, moved files |
| HTML `src`/`href` resolution | broken stylesheet and script links |
| Bare imports vs `package.json` | undeclared dependencies |
| Named imports vs target's exports | `import { x }` where the module never exported `x` |
| `\`` detection | template literals pasted escaped |
| ~20,000-byte file size | chat-window truncation |
| `def init(self` in Python | dunders eaten by a Markdown renderer |

It exits non-zero on any error, so it can gate CI. Comments are blanked before
the import scan so example code inside `/* */` is not reported — the naive
version produced two false positives on this repo.

**One practical habit** avoids nearly everything in Part 1: when copying code
out of a chat, use the code block's copy button rather than selecting rendered
text, and check the byte count of anything that lands near 20 kB.
